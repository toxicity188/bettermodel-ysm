# BetterModel YSM

A standalone Paper plugin that adds `.ysm` model support through BetterModel's public importer API. It converts YSM assets to BBModel and loads them through BetterModel's existing model pipeline.

## Requirements

- Paper 26.3
- Java 25
- BetterModel 3.7.0-SNAPSHOT
- Access to Maven artifacts on the first server startup for runtime libraries

## Installation

1. Build with `./gradlew build` on Linux/macOS or `.\gradlew.bat build` on Windows.
2. Copy `build/libs/bettermodel-ysm-1.0.0.jar` into your server's `plugins/` directory. The `-plain.jar` artifact is not the deployment JAR.
3. Start the server with BetterModel installed.
4. Place `.ysm` files in BetterModel's existing model directory, then reload BetterModel.

The plugin registers its importer during `onLoad()`, before BetterModel's initial model loading. BetterModel discovers files by extension and invokes registered importers through its normal loading pipeline.

## Converted models

Converted files are saved to:

```text
plugins/BetterModelYsm/converted/<model-name>-<SHA-256>.bbmodel
```

The hash includes the original asset's `ModelAsset.rawName()` and `name()`. Assets with the same model name in different source paths receive separate output files. Output names are sanitized, and source paths are never used as output subdirectories. Moving or renaming a source creates a new output identity. BetterModel's own model-name conflict rules still apply.

### Editing and reconverting

Existing converted files always take priority. You can edit a generated BBModel file, and the plugin will reuse it without opening the original YSM or comparing modification times. Updating the YSM does not overwrite your edits.

To reconvert a model:

1. Back up or move its generated BBModel file outside its original output path.
2. Reload BetterModel.

An invalid edited BBModel is not automatically repaired or replaced from the YSM source. Check the server log and correct the file.

New conversions are written to a temporary file in the output directory and validated by BetterModel's `ModelImporter.BBMODEL` before publication. Publication never replaces an existing output. Conversion failures are logged with their cause and path, and existing files are preserved. Shared locks coordinate parallel imports targeting the same output, including across importer instances.

## Compatibility

YSM Converter's format limitations and texture-selection warnings appear in the server log. This plugin does not add YSM-specific scripting or execution features. BetterModel's standard BBModel importer handles the converted model data.

## Building

The project includes a Gradle 9.9.1 wrapper and uses Maven Central, the Paper repository, and GitHub Packages.

```sh
./gradlew build
```

On Windows:

```powershell
.\gradlew.bat build
```

If GitHub Packages requires authentication, set `githubPackagesUsername` and `githubPackagesPassword` in your user-level Gradle properties, or use the `GITHUB_USERNAME` and `GITHUB_TOKEN` environment variables. Do not commit credentials.

Builds have been verified offline using cached BetterModel 3.7.0-SNAPSHOT and YSM Converter 1.0.0 artifacts. A fresh environment needs permission to download those artifacts.

### Packaging and runtime libraries

The deployment JAR bundles only YSM Converter, relocated into a private package, and preserves its license notices. Converter transitive dependencies, Paper, and BetterModel APIs are not bundled.

Gson is supplied by Minecraft. The generated plugin descriptor declares these runtime libraries for Paper to download with their transitive dependencies:

- `com.github.luben:zstd-jni:1.5.7-25`
- `com.twelvemonkeys.imageio:imageio-core:3.15.3`
- `com.twelvemonkeys.imageio:imageio-jpeg:3.15.3`
- `com.twelvemonkeys.imageio:imageio-webp:3.15.3`

The server must be able to reach these Maven artifacts on first startup. The plugin registers the library loader's TwelveMonkeys image readers and deregisters them on shutdown.

`plugin.yml` is generated by jpenilla resource-factory's Bukkit convention and declares `depend: [BetterModel]`.

## Tests

```powershell
.\gradlew.bat test
.\gradlew.bat test '-PysmTestModel=C:\models\example.ysm'
```

The default tests generate an original cube and PNG, encrypt them with AES-CBC, and compress them with zlib to create a valid YSM V1 fixture. No external model or network access is needed for the fixture. Tests cover conversion, actual `ModelImporter.BBMODEL` loading, edited-file preservation, explicit reconversion, parallel imports, path collision prevention, stream closure, and preservation on failure.

Only BetterModel's platform boundary is substituted in tests; the actual BBModel parser and blueprint generation run. The deployment JAR is also tested in a separate class loader with parent-provided Gson, ImageIO services, and the native zstd codec.

Set `ysmTestModel` to test an external encrypted YSM file. External models are not copied into this project, and testing does not imply permission to redistribute them.

These tests do not launch a Paper server. In-game rendering and resource-pack delivery require server-side verification.
